청크 구조 예시 도식 (Metadata 무결성 강조)

1. 개요

이 도식은 LangChain의 Document 객체가 벡터 DB에 저장되기 위해 최종적으로 갖는 구조를 보여주는 기술 설계도입니다. LLM 담당자의 핵심 설계 목표인 **메타데이터 무결성(NF-E3)**을 증명하는 근거 자료입니다.

2. 청크 구조의 핵심 구성 (시각화)

요소

내용

설명 (RAG 프로젝트에서의 역할)

Page Content

"2025년 10월 1일, 제주 서귀포시... 거래금액 28,200만 원에 중개 거래되었습니다."

[임베딩 대상] 청킹 및 정제된 자연어 팩트 텍스트 본문이다. LLM 프롬프트 {context}에 삽입되는 자료이다.

Metadata

{...} (JSON 형태)

[2차 검증 연결 고리] 팩트 본문에 대한 정형화된 꼬리표이며, RDB ID와 계약일이 포함된다.

Vector

[768차원 벡터 데이터]

[검색 대상] Page Content를 KO-SBERT가 변환하여 생성한 숫자 좌표이다.

3. Metadata 필드 상세 규격

필드 명칭 (Key)

데이터 타입

프로젝트 내 역할 (필수성)

rdb_id

String/Integer

[최상위 필수] 벡터 DB 검색 후 RDB 원본 데이터를 조회하여 최종 시세 숫자를 검증하는 유일한 연결 고리이다.

contract_date

String

출처 명시(Citation) 및 최신성 검증을 위해 사용된다.

document_type

String

데이터의 유형(XML 원본, RSS 뉴스 등)을 구분하여 **성능 분석(M5)**에 활용된다.

4. 구조의 전략적 의미 (시각적 증명)

이 도식은 Metadata 내부에 **rdb_id**가 명확히 존재함을 보여주어, LLM 담당자가 청킹 단계에서부터 2차 검증 로직을 고려했음을 시각적으로 입증하는 자료이다.
